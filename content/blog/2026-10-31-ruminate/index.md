# はじめに

Claude Code や claude.ai と毎日のように話しているのですが、会話の中で「なるほど」と思ったことを翌週にはきれいに忘れている、ということが増えてきました。調べ物も設計の相談も AI 相手に済むようになった分、自分の頭を通らずに流れていってしまう感覚があります。

ちょうど『科学的根拠に基づく最強の勉強法』を読んで、覚えるには読み返すのではなく思い出す練習をするのがよい、というのを知ったので、AI との会話をためておいて、そこから復習問題を作って毎晩出題してもらう仕組みを作りました。[ruminate](https://github.com/futabooo/ruminate)（反芻する、の意味）という名前にしています。

この記事では、本の方法をどう仕組みに落としたか、1 日の流れ、作る途中でつまずいたことを書きます。

https://github.com/futabooo/ruminate

# 全体の構成

会話を集める側と、問題を出す側に分かれています。会話のログは非公開のリポジトリ（`ruminate-data`）にためて、コードは公開のリポジトリ（`ruminate`）に置いています。

![ruminate の全体構成。パソコンの Claude Code と claude.ai の会話を非公開リポジトリにためて、毎晩のタスクが GitHub Issue に出題し、Actions の Claude が採点する](./assets/overview.svg)

集める側は 3 本あります。

- **Claude Code**: ターミナルで会話が終わるたびに、プラグインのフックから `ruminate sync` が動いて会話を変換して push します。会話ファイル（`~/.claude/projects/` の JSONL）から本人の発言と Claude の返答の文章だけを取り出し、ツールの実行結果や思考、サブエージェントの会話は捨てます。API キーや電話番号らしい文字列は伏せ字にします
- **claude.ai の会話**: 手元から読む方法がないので、claude.ai のチャットで「ruminate 取り込み」と頼むと動く Skill を作りました。過去チャット検索で直近の会話を集め、GitHub コネクタで直接リポジトリに書きます。公式のエクスポートを `ruminate import` で入れる道も用意していて、どちらで入れても同じファイル名になるので重複しません
- **出題と採点**: claude.ai のスケジュールタスク（Claude Code タスク）が毎晩 `ruminate-data` を読んで 3 問作り、GitHub Issue に立てます。自分が Issue にコメントで答えると、GitHub Actions で動く Claude が数分で採点と講評を返して Issue を閉じ、記録を `review/` に書きます

データは全部 JSONL で、見るときは DuckDB です。`ruminate db` と打つとビューが用意された状態で DuckDB が開いて、`SELECT * FROM sessions` のように会話を横断して検索できます。

```

│    agent    │   project    │   started   │ prompts │ turns │                title                │
```

# 本の方法をどう仕組みに落としたか

本で紹介されている方法のうち、仕組みで強制できるものを選びました。

| 本の方法 | 仕組みでの形 |
|---|---|
| アクティブリコール（思い出す練習） | 会話を読み返させず、「なぜ」「どう違う」の形の問いを Issue で出す |
| 分散学習（間隔を空けて繰り返す） | 問題ごとに段階を持ち、正解すると翌日 → 1 週間後 → 1 か月後と間隔が延びる。間違えると翌日に戻る |
| 交互学習（別の話題を混ぜる） | 1 晩の 3 問は別々の話題から。同じ会話から 2 問続けない |
| 自己説明（理由を自分の言葉で言う） | ○× の自己採点ではなく、答えを文章で書く。説明がない一言は × |
| すぐのフィードバック | 答えを書いたら数分で講評が返る。模範解答も Issue の折りたたみに入れてあり、書いたあとに自分で確かめられる |

最初は「答えを同じ通知に入れて自分で ○× を付ける」設計にしていたのですが、それだと答えを見てから分かった気になるだけなので、文章で書いて Claude に採点してもらう形にしました。答えを書く手間は増えますが、それ自体が自己説明なので、ここは手間をかける価値があると思っています。

# 1 日の流れ

毎晩 21 時に GitHub から通知が来ます。Issue にはこんな問題が並びます。

> 1. Android 14 以降で Google が Play 経由でルート証明書を更新しても、旧 Dart SDK でビルドしたアプリの dart:io の HTTPS が守られないのはなぜ？
> 2. Claude のサブエージェントと herdr で立てるエージェントでは、実体と人間の介入のしやすさがどう違う？
> 3. push.default = current の状態で push.autoSetupRemote = true を足すと、新しいブランチの初回 git push で何が変わる？

どれもここ 1 週間の Claude Code での会話から作られたものです。コメントに答えを書くと、数分でこう返ってきます。

> 採点: ○ 0 / × 3
>
> 1. × 「OS の証明書を使っていない」というより、旧 Dart は固定パス /system/etc/security/cacerts を読んでいて、Play で更新される Conscrypt APEX のストアを見ていないのが核心です。「古い置き場所を見続けている → SDK を上げて再ビルド」で覚えましょう。
> 2. × herdr 側が独立していて対話的、までは方向が合っています。ただ、サブエージェントは親の中の使い捨て呼び出しで途中が見えず要約だけ返る点、herdr は別ペインの独立プロセスで会話が見え、承認ダイアログに人間が直接答えられ、親が落ちても残る点が抜けています。
> 3. × push.default = current ならリモートブランチはもともと作られます。autoSetupRemote で増えるのは「-u なしでも追跡（upstream）設定まで自動でされる」ことです。

初日は 3 問とも × でした。会話したときは分かったつもりだったのに、核心を自分の言葉で言えていない、というのがはっきり出ていて、作った甲斐があったなと思っています。間違えた問題は翌日にもう一度出ます。

# 設計で決めたこと

- **コードと個人データを分ける**。会話ログには仕事の話も家庭の話も混ざるので、コードは公開、データは非公開の別リポジトリにしました。仕事のプロジェクトは設定で最初から除外できます
- **1 会話 1 ファイル、変わったら丸ごと作り直す**。Claude Code の会話ファイルは追記しかされないので、更新の検出はサイズと更新時刻を見るだけで済みます。ファイル名は会話の開始時刻と ID から決まるので、どの経路で入れても同じ場所に上書きされます
- **Markdown は置かない**。人が読む用のファイルは作らず、JSONL だけを置いて DuckDB で読みます。探す・絞る・数えるには十分ですが、1 つの会話を通して読むには表は向いていないので、各行に元の会話の URL を持たせて、読みたいときは claude.ai や `claude --resume` で元の会話に戻る前提です。出題タスクも DuckDB か jq で読めばよく、整形の手間がありません
- **同じファイルを 2 か所から書かない**。`logs/` はパソコンと取り込み、`review/` は出題と採点だけが書く。push の前に `pull --rebase` するので、同じ夜に複数が push してもぶつかりません

# つまずいたこと

作る過程で分かったことをまとめておきます。2026 年 10 月末時点の話なので、変わっているかもしれません。

- **claude.ai のスケジュールタスクには過去チャット検索がない**。最初は「毎日 claude.ai の会話を拾うタスク」を作ろうとしたのですが、リポジトリを指定しても指定しなくても、タスクの環境には検索ツールが出てきませんでした。設定で「チャットの検索と参照」をオンにしていても同じです。普通のチャットには検索があるので、取り込みは Skill にして自分が一言頼む形にしました
- **リポジトリを指定したタスクは Claude Code タスクになる**。`git` と `gh` が使えて、`main` に直接 push もできました。一方で作業用の `claude/…` ブランチが残ります
- **普通のチャットの GitHub コネクタは main に直接書ける**。接続の確認は出ますが、ファイルの作成と更新ができました。取り込み Skill はこれで書いています
- **GitHub Actions の OIDC の `sub` が 2026 年 7 月 15 日以降に作ったリポジトリでは変わっている**。採点の Action は Anthropic の Workload Identity Federation で認証していて（リポジトリに API キーを置かない）、ルールの subject を `repo:futabooo/ruminate-data:ref:refs/heads/main` と書いたら一致せず、実際は `repo:futabooo@944185/ruminate-data@1436689485:ref:refs/heads/main` のように数値 ID が入る形式でした。Console の認証イベントに `match_subject_prefix` と出て気づきました
- **Console のクレジットが 0 だと、認証は通るのに API 呼び出しが失敗する**。Action のログには理由が出ず（ツールの出力を隠す設定なので）、認証イベントは成功になっていて、しばらく悩みました。クレジットを入れたら動きました
- **伏せ字は正規表現なので完全ではない**。仕事のプロジェクトは除外する前提で、安全網としてだけ使っています

# これから
